# 010：eBPF sockmap 转发，由监听器的 `sockmap` 开启，属于 akit 扩展

[English](010-sockmap-relay.md) | [简体中文](010-sockmap-relay.zh-CN.md)

状态：I51b 中接受（2026-11-25）。

## 背景

akio 可以用 eBPF sockmap（`akio::ebpf::Relay`）在内核中把两个 TCP 套接字拼接起来：拼接之后，一个套接字收到的数据
直接从另一个发出，不再唤醒用户态。这正是 `tcp` 服务在上游连上之后对每个连接所做的事，路线图也把它列为 akio 给 akit
带来的、fit 没有的收益之一。这个转发需要 `CAP_BPF` 和 `CAP_NET_ADMIN`（或 `CAP_SYS_ADMIN`），以及 Linux 6.15 或更新
的内核（更早的内核在发送缓冲区满时可能丢失转发的字节）；被拼接的套接字的字节从不到达代理，代理只能通过套接字的 TCP
计数看到它们。

fit 没有这样的转发，也没有对应的字段：它的引擎 fib 没有 sockmap，fit 的 `services` 和 `listeners` 也没有这个字段。
[决策 002](002-config-compatibility.zh-CN.md) 让 fit 主导配置结构：akit 不增加 fit 不会接受的字段；对 akio 能做而 fib
不能做的事，字段要向 fit 提出，fit 可以接受它并忽略它。

## 决策

- **`listeners[].sockmap` 是 akit 的扩展字段**，布尔值，省略时为 false。带有它的 `tcp` 监听器，在转发能加载的地方，
  其服务的连接在内核中拼接；在不能加载的地方，像以前一样在用户态转发。它属于监听器而不是服务：路线图让监听器提出这个
  要求，一个服务可以有多个监听器，而是否拼接更多取决于端口（它的客户端、信任关系），而不是上游。协议中没有 `tcp` 的
  监听器写了它会被拒绝。重新加载改变它时，对之后接受的连接生效，不需要重新绑定监听器。
- **它不在 fit 的字段清单中。** akit-config 把它与 fit 的字段分开列出（`LISTENER_AKIT_ONLY`），`.conf` 的读取器和
  写出器从 akit 扩展字段的列表中得知它的类型，兼容性闸门检查这样列出的字段没有一个是 fit 已有的：如果 fit 采纳了它，
  就把它移到 fit 字段的列表。按照决策 002，这个字段要向 fit 提出，fib 可以接受它并在用户态转发，就像 akit 在没有内核
  转发时那样；在 fit 采纳之前，设置了它的配置只属于 akit，fit 会把它当作未知字段拒绝。
- **从不导致失败。** 转发无法加载时（没有权限、内核太旧、不是 Linux），在标准错误上说明一次，这些监听器在用户态转发；
  转发无法接手的单个连接也是如此。配置的含义不随主机改变：两种方式下字节、顺序、超时和关闭都相同。
- **使用 akio 的转发，通过计数观察。** 转发是 akio 的，在绑定或重新加载监听器的地方每个进程加载一次，从不在 I/O 线程上
  加载。akit 读取已拼接连接的 TCP 计数，用于空闲超时，并且只有在内核把一侧收到的数据都转发完之后才关闭另一侧。akio
  目前没有公开的方法拿到连接的套接字来读这些计数：akit 使用文档中隐藏的 `Conn::inner`，这是一个临时方案，记录在
  [akio API 请求 A170](../akio-api-requests.zh-CN.md#a170-连接的-tcp-计数以及先写数据再拼接) 中。

## 影响

- 在具备权限的 Linux 6.15+ 上，`tcp` 服务的字节不再经过 akit：没有拷贝，没有唤醒，没有用户态背压；内核转发的积压由
  套接字的缓冲区限定，而不是由 akit 的水位线限定。
- 使用 `sockmap` 的配置在 fit 采纳该字段之前不是 fit 的配置；不使用它的配置不受影响。对不使用它的配置，在 fit 和 akit
  之间切换仍然只是替换二进制。
- 已拼接连接的情况只能通过计数看到：它的空闲超时由服务的清扫检查（超时的四分之一，最多一秒），而不是按每个字节检查。
- 监听器读取了 PROXY 头的连接仍在用户态转发，直到 akio 能说明那个头有多长（A170）。
