# 029: The v1 freeze: baselines, marked changes, and two checks

[English](029-v1-freeze.md) | [简体中文](029-v1-freeze.zh-CN.md)

Status: accepted in I79 (2026-11-26).

## Context

fit froze its config schema and Admin API as v1 in its I77 ([fit's policy](https://github.com/lesismal/fit/blob/main/docs/compatibility.md)):
a written policy, `schema_version`, and old names of renamed fields read with a warning. Its schema
is generated from its Go types, so a change to the config shows in the schema's diff in review.
akit's config is fit's, read by hand-written decoders, and its Admin API answers are written by
hand: nothing would show a change that breaks a 1.x promise unless a check looks for it.

## Decision

- **The v1 surface is written down once**, at the freeze, in [tests/compat/v1](../../tests/compat/v1):
  the config's (every field of fit's schema version 1 with its type, requiredness and default, the
  enums' values, the deprecated names, the fields akit reads, akit's extensions), generated by
  `tools/v1-freeze.py --write-baseline`; and the Admin API's (endpoints, header fields, the query
  parameter, the members of a change's, an error's and `GET /versions`' answers), written by hand.
  `tools/v1-freeze.py` holds both files' SHA-256: editing a baseline is a new version.
- **Every change since is marked** in `additions.txt`: `added` for a compatible addition,
  `retired` for what the policy lets a 1.x release change (a default tightened for security), with
  why. `make v1-bless` marks the config's additions and never a breaking change.
- **Two checks**: `tools/v1-freeze.py` in CI's lint job builds the config's surface from fit's pinned
  schema and `supported.txt` and fails on any difference not marked; akit-admin's
  `v1_surface_is_frozen`, in every test job, runs the Admin API and probes it against its surface.

## Consequences

- An iteration that makes akit read a field, or a pin that brings fit's new fields, runs
  `make v1-bless` in the same commit; a review sees the addition in `additions.txt`.
- The Admin API check finds a new path only where the dispatcher names it as a string literal (it
  reads `server.rs`'s `call`), and checks the members of three answers, not of `/status`,
  `/config/effective` or `/cache`; those stay held by their own tests and by review.
- Branches that add supported fields in parallel each mark their own additions; merging them
  concatenates the lines.
