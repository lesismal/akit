# M3 report, 2026-11-25

[English](m3-report-2026-11-25.md) | [简体中文](m3-report-2026-11-25.zh-CN.md)

The end of M3, gateway features (I39–I55, with I51b), checked by I56: the roadmap's
[exit criteria](../../docs/roadmap.md#m3-gateway-features), each middleware's benchmark against
fit's, and the full harness with every server ([rule 28](../../docs/rules.md#12-benchmark-reports)).
akit at `8413090` (the module runs at `2a1422d` and `8413090`, the same akit code), akio at
`dad77a7a`, fit at `7daee573` (`bench/FIT_REV`).

- **Every exit criterion holds.** I56 adds the check that no module blocks an I/O thread (fit's
  `test/workers`, onto akio's slow-callback detector) and the two slow-peer tests that were
  missing (a WebSocket's slow upstream, UDP), and a benchmark of every middleware against fit's.
- **Each middleware costs akit what it costs fit**, within a microsecond a request, but gzip
  (+6.7 µs against +3.9), `wasm` (+13.6 against +6.4) and `forward_auth` (+20.4 against +17.0).
- **akit leads** fixed responses (HTTP/1.1, h2c, h2) and static files (HTTP/1.1, h2), is 2nd in
  static h2c (98% of fit) and in idle memory, and **3rd in the proxy** (88–95% of the leader), as
  at M1.
- **HTTPS/1.1 answers nothing and the proxy's memory grows** at akit's akio pin: akio API requests
  A172 and A171, found and fixed on akio branches by I25, not on akio's main yet.

### No module blocks an I/O thread

`crates/akit/tests/workers.rs` is fit's `test/workers` (fit's I55) ported onto akit's listener.
Every module akit's binary registers, the 14 middlewares and the 5 handlers, serves a request whose
answer waits 600 ms on something slow: every middleware wraps a `proxy` to an upstream that answers
600 ms later; `forward_auth`'s auth service is the slow one; `fastcgi`'s application answers late;
`forward_proxy`'s tunnel goes to an echo that answers late; `basic_auth` checks a bcrypt hash on
akio's pool; `wasm` runs fit's test plugin on its instance pool. Where fit times `ServeHTTP` against
200 ms, akit has akio time every callback on its I/O threads: the engine's slow-callback detector,
set to 200 ms, must record none, while each answer comes only after the slow part (but for
`redirect`, `respond` and `static`, which answer themselves). A middleware made to sleep 300 ms
in its call fails the test, naming it. `every_module_covered` fails for a module registered without
a case, so a new one cannot skip the check. Unlike fit's, no module is left out: the CONNECT of
`forward_proxy` and the plugin of `wasm` are served here too.

### Slow peers

| Proxying | Slow client | Slow upstream | Other ends |
| --- | --- | --- | --- |
| WebSocket from HTTP/1.1 | `websocket_backpressure`: a client that reads nothing holds a 64 MiB flood to under half in 1 s, then gets all of it | `websocket_slow_upstream` (new): a client's 64 MiB flood to an upstream that reads nothing is held to under half, then arrives whole and in order | echo, refusals, idle timeout, the pool |
| WebSocket from h2c (RFC 8441) | `h2c_backpressure_and_other_protocols`: a peer that returns no window holds the flood | not tested apart from HTTP/1.1's | h2 over TLS and h3 echoes |
| WebSocket from HTTP/3 (RFC 9220) | `h3_backpressure`: a stream whose reads are held | not tested apart from HTTP/1.1's | |
| gRPC, h2c and h2 upstreams | `backpressure` (fit's `TestGRPCBackpressure`): a client that reads nothing holds a 32 MB server stream | the same test: an upstream that reads nothing holds a 32 MB client stream | `unary`, `server_streaming`, `client_streaming`, `bidi_streaming`, deadlines, an upstream gone |
| TCP | `tcp_slow_client`: 64 MB held to under half | `tcp_slow_upstream`: the same the other way | echo, hang-ups, idle, `max_conns`, reload |
| UDP | `udp_slow_peers` (new): a client that reads nothing while its upstream floods it keeps its session | the same test: an upstream that answers one session 600 ms late holds no other session back | sessions, expiry, `max_conns`, reload |

fit has no slow-peer test for UDP; `udp_slow_peers` is akit's. A datagram is not held back the way a
stream is: what a client does not read, the kernel drops, and what is checked is that akit neither
waits nor keeps it.

### One port

`one_port.rs`'s `sniff_clear` serves HTTP/1.1, h2c, TLS passed through by its server name, SOCKS5
and SOCKS4, and raw TCP on one listener in the clear (fit's `TestSniffClear`); `socks_beside_https`
serves HTTPS over HTTP/1.1 and h2, TLS passed through by SNI, SOCKS5 and raw TCP on one TLS
listener (fit's `TestOnePortManyProtocols`, its listeners "one" and "three").

- **What a middleware costs akit is what it costs fit**, within a microsecond, for the
  middlewares that decide inline: `rewrite`, `headers`, the three limits, `basic_auth` with a
  remembered password, `client_cert`, `circuit_breaker`, and `compress` on a response it leaves
  alone add 0 to 0.9 µs to akit's request and 0.3 to 1.2 µs to fit's. `jwt` adds 1.9 to 2.4 µs
  against fit's 1.1 (a token kept verified: a SHA-256 of it and a per-thread map). Their
  throughput follows the proxy's: what separates akit from fit on these routes is the proxy
  under them, not the middleware.
- **`forward_auth`** asks the backend on every request, a second exchange: 20 µs in akit, 17 in
  fit, at 97–98% of fit's throughput.
- **`compress` gzipping** the 1 KiB (`compress_gzip`, `min_bytes` 512, gzip at fit's default
  level) costs akit 6.7 µs a request against fit's 3.9: akio-deflate's gzip against Go's
  `compress/flate`, the second place where akit's middleware is slower than fit's.
- **`wasm`** is where akit is furthest behind: +13.6 µs a request against fit's +6.4, 64% of
  fit's throughput. akit runs fit's Go plugin on akio-wasm's interpreter, on its instance pool
  off the I/O threads ([decision 008](../../docs/decisions/008-wasm-runtime.md), I71); fit runs it
  compiled by wazero.
- **Answered without the upstream**, akit is ahead: `respond` 812k requests a second against fit's
  780k, `redirect` 815k against 765k, `cache` hits 782k against 755k, with a p99 of 0.3–1.8 ms
  against fit's 0.8–2.8.
- **The proxy itself** is where akit is behind fit: `none`, 226k (epoll) and 233k (io_uring)
  against fit's 268k, 28.3 and 27.5 µs of CPU a request against 21.1. The same gap shows in the
  full harness's proxy scenario below and in I25's M1 runs; it is the proxy core's (M1), not
  M3's. akio's A171 (below) is part of it: I25 measured 3% more requests a second with it fixed.
- **io_uring** gives akit 2–4% more than epoll on the proxied routes, and the same on the ones
  answered inline.


## The full harness

fit's harness with every server ([`m3-2026-11-25`](m3-2026-11-25), `bench/run.sh` at `8413090`):
nginx, Caddy, Traefik, fit and akit; the fixed, static and proxy scenarios over HTTP/1.1, HTTPS/1.1,
h2c and h2; idle HTTP/1.1 and TLS connections, 10,000 of each. The host and the settings are the M1
baseline's (`baseline-2026-11-24`): AMD Ryzen 7 7800X3D, 16 threads, the server on CPUs 0-6, the
load generators on 7-13, the backends on 14-15; 30 s runs after 5 s of warm-up; wrk with 256
connections, h2load with 64 connections of 32 streams. akit runs `akit run`, which serves on epoll
(it cannot choose io_uring yet: the module benchmarks above have both).

**Two akio defects show in this run, both found by I25 (the M1 report) and fixed on akio branches
that are not on akio's main yet**, so akit's pin (`dad77a7a`) still has them:

- **HTTPS/1.1 answers nothing** (0 requests, 2 million errors): akio-tls refuses a ClientHello whose
  SNI is an IP literal, which wrk sends for `https://127.0.0.1/`. akio API request
  A172 (in I25's branch, `claude/i25-m1-report-77689c`, until it merges); with it, I25's run measured akit at 621k (fixed), 589k
  (static) and 230k (proxy) requests a second over HTTPS/1.1, ahead of fit's and nginx's in the
  first two.
- **The proxy's memory grows with its requests** (1.8 GiB at the end of each proxy run): akio-http's
  timer thread keeps every client request's timeout job until its timeout passes. akio API request
  A171 (I25's too); with it, I25's run measured akit's proxy at 11 to 27 MiB.

Neither is M3's: both are on the M1 paths, and I56 leaves them to I25's requests rather than
measure the same fixes again.

### Against M1

M3 adds nothing to the fixed, static and proxy paths unless a config asks for it, and the numbers
say so: akit's are within 3% of I25's M1 run (`m1-2026-11-25-akio-fixes`, same host, hours apart)
where both answered: fixed 830k against 814k (HTTP/1.1), 5.57M against 5.53M (h2c); static 788k
against 791k (HTTP/1.1), 3.01M against 3.00M (h2c); proxy 240k against 245k (HTTP/1.1), 245k
against 238k (h2c), 226k against 221k (h2); idle connections 1,141 and 12,959 bytes against 1,144
and 12,942.
