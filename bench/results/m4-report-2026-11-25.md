## The Gateway API's conformance suite

Run as fit runs it ([tests/conformance](../../tests/conformance/README.md), fit's decision 012):
fit's suite module (`sigs.k8s.io/gateway-api/conformance` v1.3.0, `go test -c`), a disposable
kind cluster (v0.30.0, Kubernetes v1.34) on the benchmark host with the experimental channel's
CRDs and its pod network routed through the node, akit outside the cluster with the Kubernetes
provider (GatewayClass `akit`, controller `lesismal.github.io/akit`, Gateways on 127.0.0.1's
ports 80 and 443 and that address written into their status), `-conformance-profiles
GATEWAY-HTTP`. The suite took 77 s.

The report the suite wrote is
[tests/conformance/reports/gateway-http-v1.3.0-2026-11-25.yaml](../../tests/conformance/reports/gateway-http-v1.3.0-2026-11-25.yaml):

| Profile | Result | Passed | Failed | Skipped |
| --- | --- | --- | --- | --- |
| `GATEWAY-HTTP` core | success | 33 | 0 | 0 |

The 33: `GatewayClassObservedGenerationBump`, `GatewayInvalidRouteKind`,
`GatewayInvalidTLSConfiguration`, `GatewayModifyListeners`, `GatewayObservedGenerationBump`,
`GatewaySecretInvalidReferenceGrant`, `GatewaySecretMissingReferenceGrant`,
`GatewaySecretReferenceGrantAllInNamespace`, `GatewaySecretReferenceGrantSpecific`,
`GatewayWithAttachedRoutes`, `HTTPRouteCrossNamespace`, `HTTPRouteExactPathMatching`,
`HTTPRouteHeaderMatching`, `HTTPRouteHostnameIntersection`, `HTTPRouteHTTPSListener`,
`HTTPRouteInvalidBackendRefUnknownKind`, `HTTPRouteInvalidCrossNamespaceBackendRef`,

`HTTPRouteInvalidParentRefNotMatchingSectionName`, `HTTPRouteInvalidReferenceGrant`,

`HTTPRouteRequestHeaderModifier`, `HTTPRouteServiceTypes`, `HTTPRouteSimpleSameNamespace`,
`HTTPRouteWeight`.

The suite's other 38 tests were skipped as the suite skips what an implementation does not claim:
the profile's extended features (redirects by path, port and scheme, rewrites, mirrors, method and
query matches, response header changes, timeouts, backend protocols, listener isolation, port 8080,
static addresses, infrastructure labels) and the tests of other profiles (TLSRoute, UDPRoute, the
mesh). fit claims the same core and no extended feature (its I61); akit claims what fit claims.

No test of the claimed profile fails, so none is recorded as unable to pass. Two limits of the run:

- **epoll only.** `akit run` serves every listener on akio's default backend, epoll: it has no
  switch for io_uring (akio's `Backend` is set per listener in code, which only akit's tests do,
  through `AKIO_TEST_BACKEND`). The cluster would let akit use io_uring, as akit runs on the host
  outside it, but there is no way to ask for it. The Kubernetes provider's and the listeners' own
  tests run on epoll and io_uring in CI.
- **One address for every Gateway.** As fit, akit merges the Gateways that share a port into one
  listener, so every Gateway is reached at 127.0.0.1. The core tests do not tell Gateways apart;
  the extended `GatewayHTTPListenerIsolation` would.

### The extended features

Not run. A second run claiming the extended HTTP features akit's provider translates (method and
query matches, response header changes, path and host rewrites, redirects by path, port and
scheme, mirrors, backend request header changes, port 8080 and listener isolation, timeouts and
backend protocols), to see which would pass, waited on the benchmark host's lock behind other
sessions' benchmarks for more than an hour and was given up: it is informational, and no claim
depends on it. It is the first step towards claiming any of them.

akit's log of the claimed run held no panic and no slow-callback report from akio's detector.

## The Docker Compose example

[deploy/compose](../../deploy/compose/README.md) is fit's
[docker-compose example](https://github.com/lesismal/fit-examples/tree/main/docker-compose) for
akit: akit's image with the Docker provider (labels under `akit.`, the provider's `label_prefix`)
in front of two replicas of `traefik/whoami:v1.11.0`, whose labels are their whole routing, with
an active health check from the `akit.upstream` label. Its `test.sh` does what fit's does and one
step more:

| Step | Checked | Result |
| --- | --- | --- |
| `docker compose up` | `whoami.localhost` answers 200, from both replicas | passed |
| another host | the config's own 404 | passed |
| `--scale whoami=3` | the third replica answers once it is up | passed (one more than fit's test) |
| `docker compose stop whoami` | `whoami.localhost` answers 404 | passed |
| `docker compose start whoami` | `whoami.localhost` answers 200 again | passed |

On the benchmark host the image was akit's release binary on `ubuntu:24.04`
(`AKIT_IMAGE=...`): the host's Docker has no buildx for the repository's Dockerfile, which CI's
`packaging` job builds and the example runs there. akit applied seven versions of what the provider
provided over the run (`config version 2` to `8`), one per change the daemon's events announced.

## Where akit stands

**Against fit on M4's criteria, akit is at parity.** It passes the same 33 tests of the same
profile at the same Gateway API version, with no change to the provider ported from fit, and the
same Compose example, scripted the same way, passes. fit claims no extended feature, and neither
does akit.

**On the data plane, M4 changed nothing on the request path:** its providers, the dashboard and
telemetry are the control plane, or off unless configured (rule 24). No benchmark was run for I66
(rule 30); the full harness at the milestone's end (rule 24) is left to the separate benchmark task
([the benchmark and optimization status](../../docs/dev-plan.md#benchmark-and-optimization-status),
row "M4 exit"). The latest ranking is I25's M1 report (`abed02f`, on I25's branch, not yet on
main), by fit's benchreport scores against nginx, Caddy, Traefik and fit, with akio's A171 and A172
pinned:

| Workload | HTTP/1.1 | HTTPS/1.1 | h2c | h2 |
| --- | --- | --- | --- | --- |
| fixed | 1st | 1st | 1st | 1st |
| static | 1st | 1st | 2nd, 98% of fit | 1st |
| proxy | 3rd, behind nginx and fit | 3rd, behind nginx and fit | 3rd, behind fit and nginx | 3rd, behind fit and nginx |

Caddy is behind akit in every workload; Traefik did not start in that run. What the benchmark
task should measure for M4: the full harness with M4's build against fit, nginx, Caddy and
Traefik; and the cost of a provider at rest on a serving akit, a Kubernetes or Docker provider
watching but idle, against the same config without one (same-run A/B, alternating rounds), and
while a provider applies a new version every second (requests' p99 across the swaps).
