# M1 report, 2026-11-25

[English](m1-report-2026-11-25.md) | [简体中文](m1-report-2026-11-25.zh-CN.md)

[I25](../../docs/dev-plan.md#i25-m1-conformance-and-report): conformance runs on a development
Mac (Apple Silicon, macOS) and on the benchmark host's epoll and io_uring, and benchmarks on the
benchmark host, with akit at `00d9f18` (I25's first commits) and `9d9321e`, on akio `dad77a7a`.

- [Conformance](#h2spec): h2spec 145/145 on every HTTP/2 entry; a proxy conformance suite of
  23 cases over HTTP/1.1 and HTTP/2, which passes. It found four requests akio's servers let
  through and akit's `validate` calling a config valid that `run` refuses; akit now refuses them,
  and akio's fix is on a branch (A169).
- [Benchmarks](#benchmarks): akit is first in every fixed and static workload but static over
  h2c (98% of fit), and third in the proxy behind fit and nginx (86–93% of the best). The run
  found two akio bugs that the first numbers hid: HTTPS/1.1 from wrk failed every handshake
  (A172) and the proxy held about 240 bytes for every request of its timeout window (A171). Both
  are fixed on akio branches, not yet in akio's main or pinned; a second run measures akit with
  them.
- [Where akit stands](#where-akit-stands), and [the M1 exit criteria](#m1-exit-criteria): the
  criteria hold (conformance passes; the benchmarks and idle memory are published against M0's
  baseline, fit and nginx). Of the roadmap's performance targets, static files and fixed
  responses meet theirs; the proxy's throughput, the proxy's p99 and idle HTTP/1.1 and TLS memory
  do not yet.

## Proxy conformance

[`crates/akit/tests/conformance.rs`](../../crates/akit/tests/conformance.rs) runs the `akit`
binary in front of an HTTP/1.1 backend that records what reaches it. It passes on macOS and on
Linux (epoll; the binary's backend); akit-proxy's own tests pass on epoll and io_uring.

**HTTP/1.1**, fit's `TestProxyConformance` ported case by case, requests written byte by byte:

- refused with 400, nothing reaching the upstream: conflicting `Content-Length`s, whitespace
  before a colon, no `Host`, two `Host`s, a NUL in a field; a request with both `Content-Length`
  and `Transfer-Encoding` never lets a smuggled request through; a header past the limit gets 431;
- a bad chunk size: fit answers 400; akit, which streams a proxied body, closes the connection
  without an answer, and nothing reaches the upstream (RFC 9112 says "SHOULD respond with a 400";
  A169's fourth part);
- obs-fold is replaced with a space; `Expect: 100-continue` gets its 100 before the body, and the
  body arrives whole; an HTTP/1.0 client gets a body that is not chunked; pipelined requests are
  answered in order; an absolute-form target reaches the upstream in origin form;
- 304, 204 and 1xx from the upstream pass through without a body where there is none and the
  connection stays usable; an upstream that does not speak HTTP gives 502; `Connection: close`
  from the client closes the connection, from the upstream it stays the upstream's; the
  connection-specific fields an upstream sends (`Connection` and what it names, `Keep-Alive`,
  `Proxy-Connection`) do not reach the client.

**HTTP/2**, h2c frames written by hand, so that a request can be malformed as RFC 9113 section 8
names:

- reset or answered 400, nothing reaching the upstream: each connection-specific field
  (`connection`, `keep-alive`, `proxy-connection`, `transfer-encoding`, `upgrade`), `te` other than
  `trailers`, an uppercase name, a space in a name, a NUL, CR or LF in a value, no `:path`, no
  `:method`, an empty `:path`, two `:path`s, a pseudo-field after a field, an unknown or a
  response pseudo-field; a `content-length` the DATA disagrees with, either way;
- what reaches the upstream is HTTP/1.1: cookie crumbs joined with `; `, `:authority` as `Host`;
- what comes back is HTTP/2: no connection-specific field, 304 and 204 without a body, 1xx
  before the final response, a 128 KiB body past the initial window, an upload in several DATA
  frames, a 502 for an upstream that does not speak HTTP, the connection still usable after each.

fit's other proxy conformance points are akit-proxy's own tests over HTTP/1.1 and h2c: header
forwarding and hop-by-hop fields (`proxy.rs`, `h2.rs`), bodies streamed both ways with linked
backpressure (`stream.rs`, `h2.rs`), trailers (`failure.rs`, `h2.rs`), timeouts and client
aborts (`failure.rs`, `h2.rs`).

### Found and fixed

- **Two `Host` fields over HTTP/1.1** were served, and forwarded with the first (RFC 9112
  section 3.2 asks for 400): akio's HTTP/1 parser counted `Host` as present or not.
- **A NUL, CR or LF in an HTTP/2 field value, and a name with a space or a non-ASCII byte**, were
  accepted (RFC 9113 section 8.2.1 makes the request malformed): akio's HTTP/2 server checked
  names for uppercase only; akio's HTTP/1 client dropped the CR and LF when it wrote the request
  upstream, and wrote the NUL.
- akit-proxy now refuses both with 400, in the loop that copies the fields anyway, as fit's proxy
  checks field names (`Refused::BadFieldValue`, `Refused::TwoHosts`): a stopgap until akio's fix
  is pinned, kept afterwards as defence in depth if wanted. akio's fix (the two above and HTTP/3's
  likewise) is on akio branch `claude/a169-request-checks` (`813f53ea`), with the bad chunk size's
  400 left to do: [A169](../../docs/akio-api-requests.md#a169-malformed-requests-refused-by-akios-servers).
  With it and akit's stopgap switched off, the suite passes too.
- **`akit validate` accepted a listener with `h2c` alone**, which `akit run` refuses as not
  supported yet (akio's server always takes HTTP/1.1 as well): `validate` now says so too, and the
  compatibility gate moves fit-examples' `grpc` from valid to not supported yet (45 valid, 34 not
  supported yet). Serving h2c alone is [A168](../../docs/akio-api-requests.md#a168-http2-with-prior-knowledge-alone).

### What the first run found

- **HTTPS/1.1: no responses.** akit answered 0 requests a second over HTTPS/1.1 in all three
  scenarios (about 2 million connect errors each), while h2 over TLS worked. wrk puts the URL's
  host in the ClientHello's `server_name` even when it is an IP address (`127.0.0.1`), which RFC
  6066 does not allow, and akio-tls's server answered such a ClientHello with `decode_error`; Go's,
  OpenSSL's and nginx's servers take it as no name. Fixed on akio branch
  `claude/a172-sni-ip-literal`: [A172](../../docs/akio-api-requests.md#a172-a-clienthello-whose-server-name-is-an-ip-address).
- **The proxy at 1.8 GiB.** akit's peak memory in every proxy workload was about 1.8 GiB (fit
  28–73 MiB, nginx about 200 MiB). On the host, with wrk at 256 connections for 10s against a
  local backend, akit's memory rose by about 240 bytes a request (104, 198, 306, 437, 518 MiB at
  2–10s) and stayed after the load; the upstream connections stayed at about 220, reused. akio's
  HTTP clients queue a job on one timer thread for every request's timeout and kept it, with the
  request's exchange, until the timeout passed: with fit's 60s route timeout, a minute of
  requests. Fixed on akio branch `claude/a171-client-timer-cancel`: memory stays at 17–18 MiB and
  the proxy does 246k requests a second against 238k, in two alternating rounds of each build:
  [A171](../../docs/akio-api-requests.md#a171-client-requests-timer-jobs-cancelled-when-they-end).
- **Idle connections closed at 100k.** akit closed about 34,500 of its 100,000 idle connections
  of each kind while the rest were still opening: akio's server closes a keep-alive connection
  after 75s, fit after 120s (fib's default), as fitbench aligns every server. akit now closes
  them after 120s (`9d9321e`), and closed none in the fixed run. Its figures did not change
  (1,132 and 12,889 bytes each, then 1,132 and 12,872): the memory of the closed connections had
  stayed with akit's allocator.

### Against M0's baseline

M0's baseline ([`baseline-2026-11-24`](baseline-2026-11-24), akit `7c835ad`) measured fixed over
HTTP/1.1 and h2c and idle HTTP/1.1 at 10k; static and proxy were not served yet. On the same

| idle HTTP/1.1 at 10k (bytes) | 1,068 | 1,149 | 1,144 |

fixed over h2c is 7–8% below M0's and idle HTTP/1.1 7% above. In the first run, which ran the

over h2c likely got slower between I05 and I25 (the router, the middlewares' hooks, the metrics
and the access log's per-request reads were added in between): a same-run A/B of `7c835ad`
against `9d9321e` is the benchmark task that settles it.
